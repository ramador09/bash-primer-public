# Scaling datasets (Notebook 17)

Timing tables for the speedup/efficiency workflow. **Synthetic but realistic:**
generated by [`generate.py`](generate.py) from an Amdahl model with light, *seeded*
(reproducible) noise — so the exercises are cleanly gradeable while the curve still
"looks measured." Framed as a strong-scaling benchmark of a **DFT geometry
optimization on Euler (1–256 cores)**; physics-optional — it is just a column of
cores and seconds.

## Schema

```
cores,walltime_s
```

Deliberately plain. Notebook 17 and its `check`s key off this **schema**, not the
specific numbers, so real anonymized Alps/CSCS/Euler data can drop in later (replace
`strong_scaling.csv`) and only the answer-key constants below need updating.

## Files

| file                 | what it is                                                        |
|----------------------|-------------------------------------------------------------------|
| `strong_scaling.csv` | same problem, more cores — the main vehicle (speedup/efficiency)   |
| `weak_scaling.csv`   | constant work *per core* — for the weak-scaling stretch exercise   |
| `generate.py`        | the generator (pinned model + seed); run from the repo root        |

## Pinned model & answer key

Regenerate exactly with `python data/scaling/generate.py` (RNG **seed 1729**).

**Strong scaling** — Amdahl `T(N) = T(1)·(s + (1−s)/N)`, `T(1) = 7200 s`,
serial fraction **`s = 0.02`**, noise `±3%` (uniform) on `N ≥ 2` (the 1-core
baseline is kept exact). Efficiency `E(N) = 1/(1 + s(N−1))`.

- **Speedup/efficiency** (from the committed CSV): `E(16) ≈ 77%`, `E(32) ≈ 61%`.
- **Knee** (largest `N` with `E ≥ 0.75`): **`N = 16`**.
- **Amdahl ceiling** `S_max = 1/s = 50`; the data reaches ~42× at 256 cores.
- **Recovered `s`** from a two-point estimate ≈ `0.02` (noise makes it approximate;
  Notebook 17 grades it within a tolerance).

**Weak scaling** — `T(N) = 600·(1 + 0.04·log₂N)` with `±2%` noise; weak efficiency
`T(1)/T(N)` stays high (~76% at 256 cores), the contrast with strong scaling.
